# 06 — MVP4: Terminal panel

**Status:** researched 4 Oct 2026. Proposed, not approved. The open decisions are at the end.

**Goal:** either panel can become a real terminal, so a shell or an AI command-line tool
(Claude Code, Codex, Pi, GitHub Copilot) runs beside the file list in the same window, the way
every IDE now has a terminal pane. The terminal is a panel mode, next to the list, preview, and
info modes from MVP3.

## Verdict

- **Feasible: yes.** No terminal emulator needs to be written. A maintained .NET
  pseudo-terminal library and a headless VT emulator engine exist, both MIT and both target
  .NET 10. The work is a Terminal.Gui view that draws the emulator's cells and forwards keys,
  plus the integration with the panels. Roughly the size of MVP0, after a short spike.
- **Market: real, but narrow.** Built-in terminals with folder sync are now expected in GUI
  dual-pane file managers on the Mac. In terminal file managers, Midnight Commander and far2l
  have had a shell for decades, and one Far-style manager added a Claude Code pane in 2026.
  Nobody owns "Norton keys plus an agent pane" on macOS.
- **Common sense: only worth it if it's integrated.** myc already runs inside a terminal.
  Ghostty, iTerm2, WezTerm, and tmux all split windows, and their split will always be a better
  terminal than one drawn inside myc. A terminal panel wins only where it knows about the
  files: it opens in the panel's folder, the panel follows it, marked files go into the agent's
  prompt, and the panel signals when the agent wants you. If MVP4 ships only the emulator, it
  isn't worth the cost.
- **Recommendation: go, in three steps, gated by a spike.** Step A, a full-screen shell
  hand-off, is cheap and valuable even if the spike fails.

## Feasibility

### Build versus reuse

| Piece | Choice | Notes |
| --- | --- | --- |
| Pseudo-terminal (PTY) | [Porta.Pty](https://github.com/tomlm/Porta.Pty) 2.2.3 (1 Oct 2026, MIT, net10.0) | `forkpty` and `execvp` run in a bundled native shim (`osx-arm64`, `osx-x64`), so no managed code runs in the forked child. That is the classic .NET-on-macOS PTY trap. Read and write streams, resize, exit event. |
| VT emulator engine | [XTerm.NET](https://github.com/tomlm/XTerm.NET) 2.0.2 (MIT, .NET 10, headless) | Normal and alternate screens with scrollback, 256 and true colour, wide characters and grapheme clusters, Kitty keyboard protocol, mouse and focus events, `OSC 133` prompt marks, `OSC 8` links, `OSC 52` clipboard, `OSC 9`/`99`/`777` notifications, `XTGETTCAP` answers. Synchronized output (mode 2026) is **not** listed. |
| Proof the pair works | Iciclecreek.Avalonia.Terminal | Same author. An Avalonia terminal control built on XTerm.NET and Porta.Pty, so the PTY-to-engine wiring is already exercised. |
| Terminal.Gui view | **Ours:** `TerminalPanelView` | Terminal.Gui 2.5 has no terminal view. We draw visible cells in `OnDrawingContent`, the same way `FilePanelView` draws rows. |
| Fallback engine | [Hex1b](https://hex1b.dev/guide/terminal-emulator) 0.172 (MIT) | Its `Hex1bTerminal` is a serious headless emulator with PTY support and reflow, but it comes with its own TUI framework and is still pre-1.0. Use it if XTerm.NET fails the spike. |
| Not chosen | XtermSharp 1.0.0-alpha.10 | Still alpha. Its old Terminal.Gui v1 front-end is useful only as a reference for drawing. |

Terminal.Gui already provides two things this needs:

- **The Kitty keyboard protocol on the host.** The driver turns it on when the outer terminal
  supports it (Ghostty, kitty, WezTerm). That makes Esc, Shift+Enter, and Ctrl+Enter
  unambiguous before we pass them on.
- **Screen hand-off.** The Unix driver's `Suspend` already leaves the alternate screen,
  restores cooked mode, and restores both on resume. Step A needs the same steps, minus the
  `SIGTSTP`.

### Data path

```
child (zsh, claude, codex) ⇄ PTY ⇄ reader thread ─► XTerm.NET.Write(bytes)
                                                       │  coalesced, ~60 Hz
                                                       ▼
host terminal ◄─ Terminal.Gui diff ◄─ TerminalPanelView.OnDrawingContent (UI thread)

key press ─► Terminal.Gui Key ─► XTerm.NET GenerateKeyInput ─► PTY
replies (cursor reports, device attributes) ─► XTerm.NET DataReceived ─► PTY
```

The threading rule from [02-architecture.md](02-architecture.md#threading) holds. The PTY
reader feeds the engine off the UI thread. It only marks the view dirty, and it does that at
most once per frame through `app.Invoke`, never once per read.

### The hard parts

| # | Risk | Why it matters | Plan |
| --- | --- | --- | --- |
| 1 | **Key ownership** | Inside the terminal, the program owns the keyboard. Claude Code uses Esc (interrupt), Esc Esc (rewind), Tab, Shift+Tab, Ctrl+O, Ctrl+G, Ctrl+T, Ctrl+R, Ctrl+U, and Ctrl+A. Codex uses Esc, Tab, Ctrl+T, Ctrl+G, Ctrl+O, and Ctrl+R. Those are myc keys too. | While the terminal has focus, every key goes to the program except one reserved key, `Ctrl+]`. It is unused in Claude Code's and Codex's defaults, and it is telnet's escape key. Clicking a file panel or the bar also works. Esc then digit does not apply inside the terminal. |
| 2 | **Esc latency** | Esc is how you stop an agent. A terminal-in-terminal that waits to tell a lone Esc from an escape sequence feels broken. | The Kitty protocol removes the wait on Ghostty, kitty, and WezTerm. Measure Terminal.app and iTerm2 in the spike. |
| 3 | **Flicker** | This is the top complaint about Claude Code in tmux. Claude Code wraps redraws in synchronized output (mode 2026) only when it detects support: a `DECRQM` probe, falling back to a `TERM_PROGRAM` allowlist. | Intercept `CSI ? 2026 h/l` in the byte stream, hold the redraw until the frame ends (with a timeout), and answer the `DECRQM` probe. `CLAUDE_CODE_FORCE_SYNC_OUTPUT=1` is the documented fallback. |
| 4 | **Colours that feel native** | If ANSI colours 0–15 come out as fixed RGB values, the agent no longer matches the user's terminal theme. That is the "AI-looking" feel we avoid. | Emit indexed colours for 0–15 and the default foreground and background, and RGB only for true colour. The spike checks whether Terminal.Gui can emit indexed colours per cell. |
| 5 | **Three width tables** | XTerm.NET, Terminal.Gui, and the host each decide how wide an emoji or CJK character is. Disagreement shifts columns. | Same checks as the README's terminal check, applied to agent output. |
| 6 | **Selection and copy** | myc turns on mouse reporting, so the host's own selection needs a modifier key that differs per terminal, and it selects across both panels. | MVP4: our own drag selection inside the panel, copied through `OSC 52`. Codex and Claude Code also have their own copy commands. |
| 7 | **Scrollback** | Shells and Codex's inline mode rely on the terminal's scrollback. | Mouse wheel and `Shift+PgUp`/`Shift+PgDn` scroll the panel's history when the program is not using the alternate screen or the mouse. 10,000 lines by default. |
| 8 | **Feature detection** | AI tools turn on notifications, links, and synchronized output only when they recognise the terminal. An unknown emulator gets the plain experience. | Set `TERM=xterm-256color`, `COLORTERM=truecolor`, and `TERM_PROGRAM=myc` with a version. Answer `DECRQM` and `XTGETTCAP` honestly. Never pretend to be Ghostty. |
| 9 | **Packaging** | Porta.Pty ships a native `.dylib`. | Native AOT output is already more than one file (see the spike). The Homebrew formula installs the dylib next to `myc`. The spike checks that AOT trimming is clean. |
| 10 | **Process lifecycle** | A panel can hold a running agent. | Quit asks first when a program other than an idle shell is running. Closing sends `SIGHUP`. When the program exits, the panel says `exited 0 · Enter restarts · Ctrl+] back` and does not vanish. |

## Market

| [middle-manager](https://github.com/questdb/middle-manager) (QuestDB, Rust, Mar 2026) | `Ctrl+O` shell panel and an `F12` Claude Code panel on the opposite side, using a custom VT emulator, 10,000-line scrollback, own selection, and `claude -c` restore. | Someone has built exactly this idea. It has 6 stars and a kitchen-sink scope (CI panel, cloud protocols, hex editor). It validates the direction more than the demand. |
| yazi, ranger, lf, nnn | No terminal. They delegate to tmux or zellij. yazi's shell wrapper `cd`s to the last folder on quit. | The cheap "cd on quit" pattern belongs in Step A. |

| Captain's Deck, EmpiricCommander | A real PTY in the window, with folder sync through `OSC 7`. | Confirms that `OSC 7` is the way to sync folders. |

**Who it's for:** someone who lives in one terminal window with an agent and wants Norton file
work beside it without managing splits. People who already tile Ghostty or tmux will mostly
keep doing that. For them, Step A and the companion story already on the website are enough.

**Positioning:** the website currently says myc is the companion you open beside the agent,
then leave with F10. MVP4 adds the other half: myc can also host the agent. Both stay true.
The companion section gets one sentence once MVP4 ships, not before.

## Common sense check

- **"You're already in a terminal."** True, so MVP4 doesn't compete on being a terminal. Every
  requirement in Step C is something a host split can't do, because the split doesn't know
  which files you marked.
- **It contradicts a non-goal.** The roadmap says "no built-in shell", and MVP1 lists "a
  built-in shell or command line" as out of scope. The intent was to avoid MC's command line
  under the panels and its subshell tricks. A panel that hosts a real PTY is a different thing.
  The proposal narrows the non-goal; it doesn't drop it (decision 1).
- **It must not become an AI product.** There is no chat UI, no API keys, and no agent
  orchestration. The only AI-aware parts are launch profiles and how a profile writes a file
  mention (`@path`). Both are data in `settings.json`, not code paths.
- **Safe by default still applies.** myc never types into a terminal on its own. Text goes in
  only when you press Send, and Send never presses Enter for you. myc never types `cd` into a
  running agent. It never starts an agent on launch unless you configure that.
- **No hidden modes.** One reserved key, shown on the bar whenever a terminal has focus. No
  tmux-style prefix chords.

## Proposal

### Step A — Hand-off (small, full fidelity)

1. **Shell here, full screen** (Panel menu, `Alt+O`, the partner of `Ctrl+O` Reveal in Finder).
   myc leaves the alternate screen, puts the terminal back in normal mode, and runs `$SHELL` in
   the active panel's folder in the real terminal. `exit` returns to myc with both panels
   reloaded. This is Norton Commander's `Ctrl+O` meaning, with no emulator involved.
2. **Leave in the folder you were in.** `myc --cwd-file <path>` writes the active panel's
   folder on quit. The README gives a three-line zsh function, so F10 leaves your shell where
   you were browsing. This is the yazi pattern.

### Step B — Terminal panel

1. **Open:** `Ctrl+T` in a file panel turns the *other* panel into a terminal in this panel's
   folder, using the default profile. If that panel is already a terminal, it focuses it. The
   Panel menu gets `Terminal ▸` with one item per profile whose command is on `PATH`.
2. **Focus:** inside the terminal, every key goes to the program. `Ctrl+]` returns to the file
   panel and the program keeps running. The bar shows `Ctrl+] Back to files` and dims the
   F-keys. The F-keys stay clickable.
3. **Draw:** cells, colours (indexed where the program used indexed), bold, italic, underline
   styles, inverse, and the cursor shape. The title comes from `OSC 0`/`2`, or the profile name
   and folder. The active and inactive borders follow the theme like any panel.
4. **Resize:** a window resize or panel change resizes the PTY (`TIOCSWINSZ`), with reflow from
   the engine.
5. **Scrollback, selection, copy:** the wheel and `Shift+PgUp`/`PgDn` scroll the history. Drag
   selects, and `Ctrl+C` copies through `OSC 52` when a selection exists, otherwise it's
   `SIGINT`. Bracketed paste is passed through.
6. **Zoom:** the Panel menu's `Terminal full width` (`Alt+T` from a file panel) hides the file
   panels. `Ctrl+]` restores the layout and focuses the files.
7. **Lifecycle:** exit and restart behaviour as in risk 10. Quit confirmation names what is
   running: `Claude Code is still running in the right panel. Quit and end it?`
8. **Restore:** state remembers which panel was a terminal and its profile. On the next launch
   that panel opens a fresh *shell* in its last folder. Agents are not restarted (decision 5).

### Step C — Integration (the reason to do it in myc)

1. **Send to terminal** (`Alt+Enter`, MC's own key for "filename to the command line"). It sends
   the effective selection as one bracketed paste, relative to the terminal's folder. Shell
   profiles get shell-quoted paths. Agent profiles use their `mention` format, `@{path}` for
   Claude Code and Codex, so marking three files and pressing `Alt+Enter` puts them in the
   agent's prompt. Enter is never sent.
2. **Linked folders.** The terminal starts in the panel's folder. When the link is on, the file
   panel follows the terminal's working directory, read from `OSC 7`, or else from the child's
   `cwd` through `proc_pidinfo`. The other direction (panel to shell) only happens while the
   shell is at its prompt (`OSC 133`, or the shell owns the PTY's foreground process group),
   never while an agent or editor is running.
3. **Attention.** A bell or an `OSC 9`/`777` notification from an unfocused terminal puts `●` in
   its title and on the bar until you focus it. If Terminal.Gui allows a raw write, the same
   notification is forwarded to the host terminal so Ghostty and iTerm2 still raise their own.
4. **Profiles as data** in `settings.json`:

```json
"terminal": {
  "defaultProfile": "Shell",
  "scrollback": 10000,
  "profiles": [
    { "name": "Shell", "command": "$SHELL", "args": ["-l"] },
    { "name": "Claude Code", "command": "claude", "mention": "@{path}" },
    { "name": "Codex", "command": "codex", "mention": "@{path}" }
  ]
}
```

The file panels already reload when another program changes a folder, so you watch the
agent's edits land in the other panel without doing anything.

## Not in MVP4

- A command line under the panels (MC and Far style), a user menu, or scripting.
- AI features of our own: chat, API keys, prompt templates, agent orchestration.
- More than one terminal per panel, or tabs.
- Sessions that outlive myc (detach and attach). That's tmux's job.
- Images in the terminal (Sixel, Kitty graphics), even though the engine decodes them.
- File paths in the output that open in the panel. A good MVP5 candidate.
- Copy or move *into* a terminal panel (decision 4).

## Spike (go or no-go)

A throwaway `spike/Myc.TermSpike` with one `TerminalPanelView` beside one file list.

1. **Programs:** zsh with a prompt theme, `vim`, `htop`, Claude Code, Codex, and Copilot CLI or
   Pi at 80×40 and 60×40. No corruption. Streaming a long diff in Claude Code doesn't tear.
2. **Keys:** Esc interrupts Claude Code at once. Shift+Enter makes a newline in Ghostty, kitty,
   and WezTerm. Ctrl+C, Ctrl+D, Tab, Shift+Tab, arrows, and Option+P reach the program.
   `Ctrl+]` reaches myc in Ghostty, iTerm2, and Terminal.app.
3. **Colours:** ANSI 0–15 match the host palette in Graphite and Paper, and under `NO_COLOR`.
4. **Throughput:** `cat` of a 50 MB log stays responsive and `Ctrl+]` still works. Idle CPU is
   about zero.
5. **Width:** emoji, CJK, and decomposed `café` line up in agent output.
6. **Mentions:** a bracketed paste of `@path` is accepted as a file mention by Claude Code and
   Codex (and doesn't just open Codex's file search).
7. **Packaging:** `dotnet publish -p:PublishAot=true` with Porta.Pty and XTerm.NET has no trim
   warnings and the binary finds its dylib.
8. **Hand-off:** Step A's leave-and-return keeps marks, cursor, and theme.

**Exit criterion:** if 1–3 pass in Ghostty and iTerm2, go. If keys or rendering can't be made
right in a few evenings, try Hex1b's engine once. If that fails too, ship Step A on its own and
move the panel back to "Later".

## Build order

1. Spike, then decide.
2. Step A: hand-off and `--cwd-file`.
3. A panel slot that can hold a different view (shared with MVP3; build it here if MVP4 goes
   first).
4. `TerminalSession` in Core: PTY, engine, resize, exit, and environment. Tested headless
   against `printf` and `stty size`.
5. `TerminalPanelView`: drawing, frame coalescing, synchronized output, and colours.
6. Keys and focus: forwarding, `Ctrl+]`, the bar's terminal state, paste, and mouse.
7. Scrollback, selection, and `OSC 52` copy.
8. Lifecycle: exit state, restart, quit confirmation, and restore as shell.
9. Step C: profiles, Send to terminal, linked folders, attention badge.
10. Polish: the manual terminal matrix, 80×24, very wide windows, and the README's terminal
    check extended with a terminal row.

## Definition of done

- Claude Code and Codex are usable all day in a panel in Ghostty and iTerm2, with no flicker,
  instant Esc, and correct colours.
- `Ctrl+]` always returns to the files, even while a program floods output.
- Marking files and pressing `Alt+Enter` puts them in the agent's prompt and does not submit.
- With the link on, `cd` in the shell moves the panel, and the panel never types into an agent.
- Quitting with an agent running asks first. Nothing is ever lost silently.
- A new user finds the terminal from F9 → Panel without reading docs.

## Open decisions

1. **Narrow the non-goal.** From "no built-in shell" to "no command line under the panels and
   no subshell tricks. A panel may host a real terminal."
2. **Order.** After MVP3, which builds the panel-mode slot it reuses, or pulled ahead of MVP2
   and MVP3 because it's the more distinctive feature.
3. **Keys.** `Ctrl+T` terminal, `Ctrl+]` back to files, `Alt+Enter` send, `Alt+O` shell
   hand-off, `Alt+T` zoom.
4. **F5/F6 towards a terminal panel.** Copy into the terminal's folder (shown in the dialog), or
   disabled. The proposal is disabled in MVP4. It is the safer default, and it can be added
   later.
5. **Restore on launch.** A fresh shell only (proposed), nothing, or the agent too with a
   per-profile resume argument (`claude -c`).
